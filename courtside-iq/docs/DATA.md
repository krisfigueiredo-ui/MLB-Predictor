# Dataset reference

`backend/data/demo_snapshot/` contains the dataset that ships with the repository. Each table is stored as a gzipped CSV file; `manifest.json` lists row counts and SHA-256 checksums of the uncompressed CSV content. Files are written with a fixed gzip timestamp, so re-exporting unchanged data produces identical files.

The games, statistics and odds are synthetic. They are generated by the league simulator in `backend/app/ml/synthetic.py` and every such row has `is_demo = true` (`is_historical_sim = true` for the four historical seasons). Team, school and conference records are real; NBA roster memberships are real 2025-26 affiliations marked `verified = false` until a provider roster sync confirms them.

## Tables

| Table | Description |
|---|---|
| `conferences` | NBA conferences and NCAA conferences with a prior strength (points per 100 possessions vs Division I average) |
| `teams` | NBA franchises and NCAA schools: abbreviation, location, nickname, conference, division, colors, arena, coordinates |
| `sportsbooks` | Sportsbook keys and display names |
| `players` | NBA seed roster players |
| `roster_memberships` | Player to team memberships with season, jersey number, source and verification status |
| `games` | Schedule and results: start time (UTC), teams, neutral site, status, score, first-half score, pre-game context (rest, travel, injury impact, lineup changes, roster continuity) |
| `team_game_stats` | Team box scores: points, first-half points, FGM/FGA, 3PM/3PA, FTM/FTA, offensive and defensive rebounds, turnovers, assists, possessions |
| `player_game_stats` | Player game logs: minutes, points, rebounds, assists, threes, attempts, steals, blocks, turnovers, usage |
| `injuries` | Injury reports (empty in demo data) |
| `odds_snapshots` | Timestamped sportsbook prices: moneyline (`h2h`), spreads, totals, first-half totals, team totals, alternate spreads and totals |
| `prop_lines` | Player prop lines with over and under prices |
| `demo_outcomes` | Simulated results for 2026-27 demo games, revealed by the demo feed as each game is played |
| `predictions` | Archived model forecasts with probability, line, price, result and model version |
| `settlements` | Grading records for predictions and picks |
| `model_versions` | Model registry with training window and evaluation metrics |

Column definitions match `backend/app/models.py`. Timestamps are ISO 8601 in UTC. JSON columns (`pregame_context`, `provider_ids`, `details`, `metrics`, `params`, `payload`) are stored as JSON strings.

## Commands

```bash
cd backend
python -m app.cli export-snapshot [--dir PATH]   # current database to a snapshot directory
python -m app.cli load-snapshot [--dir PATH]     # snapshot into an empty database (checksums verified)
```

When the API starts in demo mode with an empty database, it loads this snapshot automatically (`USE_DEMO_SNAPSHOT=true`), resolves any demo games played since the snapshot was taken, trains the models and rebuilds the prediction archive.
